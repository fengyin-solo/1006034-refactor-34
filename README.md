# 机场地面保障作业管理平台

面向航班保障、机位分配、廊桥靠接、摆渡车调度、行李装卸、航油加注、除冰作业与延误处置的一体化机场地面保障作业工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `airport-ground-ops:entries` 这一项，或调用 `resetModule(模块)`。

## 资源缺口测算口径

缺口测算只有一份实现：`frontend/src/domain/resource-gap.ts`。资源计划列表/导出展示、
「下发计划」落库、保障班组待办清单三个调用点全部共用，任何一处都不得自行减算。

- **扣减顺序固定为「机位 → 车辆 → 人员」**。依据是地面保障的资源依赖链：先锁停机位，
  车辆才有作业面；车辆到位后才核定机下/随车人员。机位是最硬的稀缺资源，顺序固定后，
  同一份计划在任何调用点算出的缺口都唯一、可复现。
- **单类缺口为负时截零记 0，富余不跨类抵扣**。缺口语义是「还差多少」，富余不是欠款；
  若允许人员富余冲抵机位缺口，上报总数会被抹平、掩盖真实短板。测算明细里保留
  `surplus` 备查，但「资源缺口」列、下发结论、班组待办只取非负值。
- **下发即冻结，重复下发只算一次**。缺口在「下发计划」动作里测算并写入快照；重复
  下发、越级流转都在动作受理处拒绝，缺口在计划生命周期内不回算。
- **顺序不许跨越**：资源计划只能 待编制→待审核→已下发；「作废计划」只在下发前
  （待编制、待审核）受理，已下发后任何越级动作一律拒绝。
- **历史已下发计划统一按新算法回填**：旧数据里的缺口值是代码生成器写的占位文本，
  不存在可信的旧算法结论可沿用；回填按保障时段匹配供给、一次性冻结，迁移幂等，
  已冻结的行永不重算。
- **班组待办同源**：保障班组页面的「缺口待办」只取已下发且有缺口的计划，直接读
  下发时冻结的同一份快照，按保障时段匹配在岗班组，不允许在班组侧重算。
